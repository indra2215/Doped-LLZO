Full Technical Audit: LLZO Doped Solid Electrolyte Discovery Pipeline

What This Project Is
A computational pipeline to predict room-temperature ionic conductivity (σ_RT) for aliovalent-doped LLZO (Li₇La₃Zr₂O₁₂) garnets. The workflow:

Pull base LLZO structure from Materials Project (mp-942733)
Atom-substitute known dopants, relax with MACE-MP-0 universal ML potential
Extract energy + volume → feed into GPR surrogate
Generate 10,000 virtual candidates via charge-balanced combinatorics
Pre-screen with Random Forest (Sendek-style)
MACE-relax top 50 → GPR final prediction
Validate with MD-Arrhenius backtracking

Bug #1 — ALL 154 TRAINING VOLUMES ARE IDENTICAL (Catastrophic, Data-Level)
File: bayesian_features.csv (produced by fast_surrogate_extraction.py)
Unique Volume_A3 values: 1  ← Every single sample has 1112.63 Å³

Root cause in fast_surrogate_extraction.py:

base_struct is fetched once and atoms is reconstructed from it every iteration. Symbol substitution changes element labels but not the cell geometry, lattice vectors, or atomic positions. MACE then relaxes positions inside the same starting cell. Since these structures start from identical geometry and only have different element labels, the relaxed volume stays nearly identical — MACE can't significantly change the cell because BFGS doesn't optimize the cell by default (it does constant-volume ionic relaxation unless you use a filter like StrainFilter or ExpCellFilter).
Impact: Volume_A3 is a constant feature. The GPR and RF models that use Volume_A3, Lattice_a_Ang (derived from Volume), and Volume_per_Atom are all trained on a constant dimension. The kernel sees no variance there — the model has effectively 3 useful features, not 6.
Fix:
pythonfrom ase.constraints import ExpCellFilter
from ase.optimize import BFGS

opt = BFGS(ExpCellFilter(atoms), logfile=None)
opt.run(fmax=0.05, steps=200)
This relaxes both ions AND the cell, giving physically meaningful volume per composition.

Bug #7 — MSD CALCULATION WITHOUT PERIODIC BOUNDARY CONDITION UNWRAPPING
File: step0_baseline.py (and present in backtrack_validation.py logic)
pythonmsd = np.mean(np.sum((pos_array[-1] - pos_array[0])**2, axis=-1))
When a Li+ ion crosses a periodic cell boundary, its wrapped coordinate jumps by ~12.97 Å in the opposite direction. Without unwrapped positions, MSD goes to zero every time an ion crosses a boundary, even though it has actually diffused. In a superionic conductor at 600–1000K, Li ions absolutely cross boundaries during any meaningful trajectory. This makes the diffusion coefficient systematically underestimated.
Fix:
python# Track incremental displacements
disp = np.zeros_like(positions_history[0])
unwrapped = [positions_history[0].copy()]
for i in range(1, len(positions_history)):
    delta = positions_history[i] - positions_history[i-1]
    delta -= np.round(delta / cell_lengths) * cell_lengths  # minimum image convention
    disp += delta
    unwrapped.append(positions_history[0] + disp)
Or use ase.geometry.analysis or MDAnalysis for proper unwrapping.

3. Sendek Style + GPR Full Explanation
GPR = Gaussian Process Regression
A Gaussian Process is a probability distribution over functions. Instead of learning a single function f(x) → y, GPR maintains a distribution of plausible functions consistent with your training data.
Why it works for materials:

Training data is small (154 samples here) — neural networks can't generalize, but GPR handles small-data well
It outputs uncertainty estimates alongside predictions — you know when the model is extrapolating
The kernel function encodes physical assumptions about smoothness

The math:
y = f(X) + ε,   ε ~ N(0, σ²_noise)
f ~ GP(0, k(X, X'))

k_Matern(x, x') = physical smoothness prior on energy surface
k_RationalQuadratic = multi-scale variation (different dopants affect structure at different scales)
After fitting, for a new candidate X*:
μ* = K(X*, X) · [K(X,X) + σ²I]⁻¹ · y      ← mean prediction
σ*² = K(X*,X*) - K(X*,X) · [K(X,X) + σ²I]⁻¹ · K(X,X*)  ← uncertainty
The uncertainty σ* is what makes GPR useful for Bayesian Optimization — you explore where σ* is high (uncertain regions may contain better materials), not just where μ* is high (exploitation). This is what the project intends but doesn't fully implement.
Sendek Style = Holistic Compositional Feature Screening
Sendek et al. 2017 ("Holistic computational structure screening of more than 12000 candidates for solid lithium-ion conductor materials") did:

Take 12,831 inorganic crystals from ICSD
Extract compositional and structural features (ionic radius, electronegativity, oxidation state, coordination number, etc.) — no DFT, no simulation
Train a logistic regression classifier on ~20 known Li-ion conductors vs. non-conductors
Screen all 12k candidates → identified 21 promising compounds

"Sendek-style" in your project means: using only composition-derived features (element stoichiometries) as input to a fast ML model, without running any atomistic simulation. It's a cheap first-pass filter before expensive MACE relaxation.
In compositional_screening.py, the features are just element counts [Li, La, Zr, Fe, Ga, Al, ...] — a direct Sendek-style approach. The problem is that your version uses Random Forest trained on σ_RT directly (regression), while Sendek used logistic regression for binary classification. Both are valid approaches.
The Referenced Papers
Sendek (2017): First large-scale ML screening for Li conductors using purely compositional features. No crystal structure needed — just the chemical formula.
Bianchini (2019): Extended Sendek's approach to garnet-family structures specifically, using DFT-relaxed structural features (not just composition) with a GPR surrogate. Much more similar to your project. Used AIMD at 900–1200K to compute D, then Arrhenius-extrapolated to RT.
Ahmad (2018): Applied transfer learning — trained on a broad oxide dataset, then fine-tuned on LLZO-specific data. Showed that even a small fine-tuned model outperforms a universal model for a narrow chemical space.

B. Acquisition Function for True Bayesian Optimization
Right now you generate 10,000 candidates blindly then screen them. True Bayesian Optimization would use the GPR's uncertainty to pick the next experiment, not a pre-defined grid:
pythonfrom scipy.stats import norm

def expected_improvement(mu, sigma, f_best):
    """EI acquisition function"""
    Z = (mu - f_best) / (sigma + 1e-9)
    EI = (mu - f_best) * norm.cdf(Z) + sigma * norm.pdf(Z)
    return EI

# After GPR prediction on all 10,000 candidates:
mu, sigma = gpr.predict(X_candidates_scaled, return_std=True)
f_best = y_train.max()  # best known log(sigma_RT)
EI = expected_improvement(mu, sigma, f_best)

# Select the candidate with maximum EI for next MACE evaluation
next_candidate = candidates[np.argmax(EI)]
This replaces the Random Forest pre-screening step entirely. EI explicitly trades off "probably good" (high μ) versus "we don't know yet" (high σ) — which is the entire point of Bayesian Optimization.

C. Active Learning Loop
The pipeline currently runs in one batch. It should iterate:
Iteration 1: Train GPR on 154 experimental points
             → Pick top-10 candidates by EI
             → Run MACE relaxation on 10
             → Add to training set

Iteration 2: Retrain GPR on 164 points
             → EI selects next 10 (different from iteration 1 because model updated)
             → ...
Each iteration costs 10 × ~15 min MACE = 2.5 hours on CPU. After 5 iterations you have 50 MACE-validated structures and a GPR that has specifically explored the high-conductivity region.

CHECKPOINT 1 — Crystal Structure Fundamentals
You must understand this before anything else. Everything else builds on it.
What a Crystal Structure Is
A crystal is a periodic arrangement of atoms. You describe it with:

Lattice vectors a, b, c (define the unit cell shape)
Basis (atom types + fractional coordinates inside the cell)
Space group (symmetry operations that map the crystal to itself)

LLZO cubic: Space group Ia-3̄d (No. 230)
Lattice: Cubic → a = b = c = 12.97 Å, α = β = γ = 90°
Wyckoff Positions
Every atom site in a crystal has a Wyckoff label that encodes its multiplicity and local symmetry. For LLZO:
24d  → Li+ tetrahedral sites (partially occupied)
48g  → Li+ octahedral sites (majority Li, the hopping pathway)
24c  → La³+ dodecahedral (8-coordinate) — large cations sit here
16a  → Zr⁴+ octahedral — medium cations sit here
96h  → O²- sites
Why this matters for doping: When you add Al³⁺, it must go to a site where its ionic radius fits. Al³⁺ (radius 0.535 Å in 4-coordination) fits the 24d tetrahedral Li site. Placing it on 24c (La site, 2.36 Å cavity) is physically wrong — it would collapse the cage. This is exactly Bug #4 in the archive files.
Primitive vs Conventional Cell
For LLZO (space group 230, body-centered cubic Bravais lattice):
Conventional cell: 96 atoms, V ≈ 2183 Å³, a ≈ 12.97 Å
Primitive cell:    48 atoms, V ≈ 1092 Å³  (half the conventional)

Relationship: V_prim = V_conv / 2  (BCC primitive cell = ½ conventional)
So: a_conv = (2 × V_prim)^(1/3)   ← this is the formula used in the code

CHECKPOINT 2 — Ionic Conductivity Physics
This is what you are trying to predict. You must understand what σ_RT means physically.
Ohm's Law For Ions
σ = J / E

σ = ionic conductivity (S/cm)
J = ionic current density (A/cm²)
E = electric field (V/cm)
For a solid electrolyte battery application, you want σ_RT ≥ 1 mS/cm = 10⁻³ S/cm. Current best LLZO: ~1–2 × 10⁻³ S/cm.
The Diffusion Connection — Nernst-Einstein Equation
σ = (n · z² · e² · D) / (kB · T)

n  = number density of Li+ ions (ions/cm³)
z  = charge number = 1 for Li+
e  = electron charge = 1.602 × 10⁻¹⁹ C
D  = diffusion coefficient (cm²/s)
kB = Boltzmann constant = 1.381 × 10⁻²³ J/K
T  = temperature (K)
This is why the pipeline computes D from MD, then converts to σ. You cannot directly measure D in MD — you infer it from how far Li atoms move.
Mean Square Displacement (MSD)
MSD(t) = <|r(t) - r(0)|²>

For 3D diffusion (Einstein relation):
MSD(t) = 6 · D · t

Slope of MSD vs time = 6D
Why 500 ps matters: At 600K in LLZO, D ≈ 10⁻⁸ cm²/s. In 500 ps = 5 × 10⁻¹⁰ s:
MSD = 6 × 10⁻⁸ × 5 × 10⁻¹⁰ = 3 × 10⁻¹⁷ cm² = 3 × 10⁻¹ Å²
In 0.4 ps:
MSD = 6 × 10⁻⁸ × 4 × 10⁻¹³ = 2.4 × 10⁻²⁰ cm² = 0.00024 Å²
At 0.4 ps, Li atoms have moved 0.015 Å. Thermal vibration amplitude alone is ~0.1–0.3 Å. You are measuring noise, not diffusion.
Arrhenius Behavior
D(T) = D₀ · exp(−Ea / kB·T)

Ea = activation energy (energy barrier for Li+ hopping, eV)
D₀ = pre-exponential factor (attempt frequency × jump distance²)

Taking ln:
ln(D) = ln(D₀) − Ea/(kB·T)
Plot ln(D) vs 1/T → straight line → slope = −Ea/kB → extract Ea and D₀ → extrapolate D to 298K → compute σ_RT.
This requires D values at ≥3 temperatures (600, 800, 1000K typically) for a reliable linear fit.
What Controls Ea in Garnets
Low Ea (good) → high σ_RT

Physical factors:
1. Li+ vacancy concentration  →  more vacancies = more empty sites to hop into
2. Bottleneck size            →  the triangular face between tetrahedral/octahedral sites
3. Li-O bond strength         →  weaker bond = lower hop barrier
4. Lattice parameter a        →  12.91–12.98 Å optimal (too small = tight bottleneck)

Murugan et al. 2007 (first σ measurement)

He et al. 2017 (Li+ diffusion mechanism in garnet via AIMD)
Meier et al. 2019 (activation energy vs. lattice parameter relationship)

CHECKPOINT 3 — Density Functional Theory (DFT) Basics
You need this to understand what MACE replaces and why ML potentials exist.
What DFT Solves
The Schrödinger equation for N electrons is impossible to solve exactly. DFT approximates it:
Problem:   H·Ψ = E·Ψ  (N electrons, exponential complexity)
DFT:       Minimize E[ρ(r)]  (electron density ρ only, polynomial complexity)
DFT gives you:

Ground state energy E (eV)
Atomic forces F = −∂E/∂r (eV/Å)
Stress tensor (for cell relaxation)
Electronic structure, band gap, magnetic moments

Cost: For a 96-atom LLZO cell, one DFT single-point takes ~1–4 hours on a 32-core HPC node. One geometry relaxation = ~50–200 DFT steps = days. AIMD at 100 ps = tens of millions of DFT calls = impossible.
Why ML Potentials (Like MACE) Exist
DFT accuracy + speed of empirical potentials

MACE training:  ~3M DFT calculations already done → stored in database
MACE inference: Given atom positions → predict E, F without solving Schrödinger
Speed:          1000–100,000× faster than DFT
Accuracy:       ~5–50 meV/atom vs DFT (DFT itself has ~10–30 meV/atom vs experiment)
Papers:

Kohn & Sham 1965 (original DFT — Nobel Prize)
Perdew et al. 1996 (PBE functional — most common for solids)
Jain et al. 2013 (Materials Project database — where mp-942733 comes from)


CHECKPOINT 4 — How MACE Actually Works
This is "how is it doing the relaxation" from your question.
MACE = Multi-Atomic Cluster Expansion
MACE is a message-passing equivariant graph neural network. Here is what it does step by step:
Step 1 — Build the atom graph:
Each atom = node
Bond between atoms within cutoff radius rc (~5–6 Å) = edge
Node features: atomic number Z, initial embedding
Edge features: relative position vector rij (direction + distance)
Step 2 — Equivariant message passing:
"Equivariant" means: if you rotate the crystal, the forces rotate the same way (they are vectors). If you rotate the crystal, the energy stays the same (it is a scalar). MACE uses spherical harmonics to encode directional information in a way that respects this physical requirement.
python# Each atom i collects messages from neighbors j:
message_ij = f_edge(h_i, h_j, rij)   # h = atom features, r = relative position
h_i_new = aggregate(all messages to i)

# This propagates structural information:
# Atom i "knows" about its neighbors' neighbors after 2 message-passing layers
Step 3 — Predict energy:
E_total = sum over all atoms of E_i(local environment)
F_i = -dE_total / dr_i   (automatic differentiation)
Stress = -dE_total / d(cell strain)
What "Relaxation" Means (BFGS)
Geometry relaxation = find atomic positions and cell shape that minimize E_total.
BFGS algorithm (Broyden–Fletcher–Goldfarb–Shanno):

1. Compute E and F at current positions {r}
2. Update approximate Hessian matrix H (curvature of energy surface)
3. Step: Δr = -H⁻¹ · F  (move downhill in energy)
4. Repeat until |F_max| < fmax (convergence criterion)
What changes during relaxation:
Ionic relaxation only (your current buggy code):
  - Atom positions change
  - Cell vectors fixed → Volume constant

Full relaxation (with ExpCellFilter):
  - Atom positions change
  - Cell vectors change → Volume changes
  - Both converge simultaneously
Why volume must relax for doped structures: When you replace Zr⁴⁺ (ionic radius 0.72 Å) with Ta⁵⁺ (0.64 Å), the unit cell should shrink slightly. If you lock the cell at LLZO's original volume, the Ta-O bonds are artificially stretched, giving you the wrong energy and wrong forces — the chemistry is unphysical.

CHECKPOINT 5 — Molecular Dynamics Theory
Why MD works and what its limitations are.
Newton's Equations for All Atoms
F_i = m_i · a_i = m_i · d²r_i/dt²

Given F from MACE:
1. Compute acceleration a_i = F_i / m_i
2. Update velocity: v_i(t+dt) = v_i(t) + a_i · dt
3. Update position: r_i(t+dt) = r_i(t) + v_i(t+dt) · dt
4. Compute new F from MACE at new positions
5. Repeat
This is the Verlet integration. ASE uses a velocity Verlet variant.
Timestep Choice
dt must be << fastest atomic vibration period

O-H stretch: ~10 fs period → dt ≤ 1 fs
Li-O stretch in LLZO: ~20–30 fs period → dt = 2 fs is safe
Your code uses 2 * units.fs — correct for LLZO. Going to 5 fs would cause energy drift (instability).
NVT Ensemble and Langevin Thermostat
NVT = constant Number of atoms, Volume, Temperature (canonical ensemble)
Physical meaning: your crystal is in contact with a heat bath at temperature T

Langevin equation:
m·a_i = F_i(MACE) − γ·m·v_i + η_i(t)

F_i      = deterministic force from MACE
−γ·m·v_i = friction term (removes energy → prevents overheating)
η_i(t)   = random force (adds energy → prevents freezing)
Balance: <KE> = (3N/2)·kB·T
friction=0.01/units.fs in your code is a reasonable choice — not too stiff (overdamped, which slows diffusion artificially) and not too loose (energy fluctuates too much).
Equilibration vs Production
When you heat a crystal from 0K to 600K suddenly:
- Initial velocities are random (Maxwell-Boltzmann)
- Positions are from the relaxed 0K structure
- Atoms need time to redistribute energy among degrees of freedom

Equilibration period: ~10–20 ps
- Energy fluctuates strongly
- MSD is not yet diffusive (still in ballistic regime)
- Discard all data from this period

Production period: After equilibration, MSD becomes linear with time
- This is where you extract D from the slope

CHECKPOINT 6 — Gaussian Process Regression (GPR) in Detail
What a Gaussian Process Is
A Gaussian Process (GP) is a distribution over functions. Instead of learning one specific function f(x), you maintain a distribution of functions consistent with your data.
Prior:     f ~ GP(μ(x), k(x,x'))
            μ = mean function (usually 0)
            k = kernel (covariance function)

Posterior: After seeing data (X_train, y_train):
            p(f* | X*, X_train, y_train) = Gaussian distribution
            Mean μ* = prediction
            Variance σ*² = uncertainty
The Kernel = Your Physics Prior
The kernel k(x, x') measures "how similar are two inputs x and x'?" — and therefore "how correlated should their outputs be?"
python# In your code:
k1 = ConstantKernel(1.0) * Matern(length_scale=..., nu=1.5)
k2 = ConstantKernel(1.0) * RationalQuadratic(length_scale=1.0, alpha=0.1)
kernel = k1 + k2 + WhiteKernel(noise_level=0.1)
Matern(nu=1.5): Assumes the function f is once-differentiable. This encodes "nearby compositions have similar conductivities" but allows sharp transitions. Appropriate for physical property-composition relationships.
RationalQuadratic: Sum of Matern kernels at different length scales. Captures both local (fine-grained compositional differences) and global (family-level) trends simultaneously.
WhiteKernel: Diagonal noise term — models experimental measurement error in σ_RT (which is substantial: different labs report the same formula with 2–5× different values).
Why GPR Works Here
Training data: 154 points
Features: 6 (Energy, Volume, a, Li_pfu, Dopant_complexity, Vol/atom)
Complexity ratio: 154/6 ≈ 25 points per feature

For a neural network: 25 points/feature = severe underfitting
For GPR: 25 points/feature = appropriate regime
GPR is exact inference (not approximate) for the Gaussian likelihood. It does not "overfit" in the neural network sense — but with a rich composite kernel and n_restarts=30, the hyperparameters (length scales, amplitudes) are optimized on training data, which IS a form of overfitting. This is why K-fold CV is mandatory.
Bayesian Optimization Flow
1. Train GPR on (X_known, y_known)
2. For each candidate x*:
   a. Predict: μ*, σ* = GPR.predict(x*)
   b. Compute acquisition: EI(x*) = E[max(0, f(x*) - f_best)]
3. Select x_next = argmax EI
4. Evaluate x_next (run MACE)
5. Add to training set
6. Repeat from 1
